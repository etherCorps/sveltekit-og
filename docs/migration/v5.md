# Migrating to v5

v5 has one API on every entry, Takumi as the default engine, and no engine installed for you. Most apps need two edits: install the engine you use, and add `engine: "satori"` if you want the output you had on v4.

## 1. Install the engine you use

v4 installed Satori and ReSVG with the package. v5 installs no engine: `takumi-js`, `satori` and `@resvg/resvg-wasm` are optional peer dependencies.

```sh
# Takumi (the default)
pnpm add @ethercorps/sveltekit-og takumi-js

# Satori (the v4 output)
pnpm add @ethercorps/sveltekit-og satori @resvg/resvg-wasm

# both engines
pnpm add @ethercorps/sveltekit-og takumi-js satori @resvg/resvg-wasm
```

Calling an engine that isn't installed rejects with `ENGINE_NOT_INSTALLED` and the exact command:

```
Engine "satori" is not installed. Run: pnpm add satori @resvg/resvg-wasm
```

The `sveltekitOG()` Vite plugin detects what you installed and keeps the other engine out of your bundle. To pin it (monorepos, or to exclude an engine another dependency pulls in):

```js
// vite.config.js
sveltekitOG({ engines: ["takumi"] });
```

`takumi-js` is no longer required to use Satori on `/client`.

## 2. The default engine is Takumi

On v4, the root entry rendered with Satori and `@ethercorps/sveltekit-og/takumi` rendered with Takumi. On v5 every entry defaults to Takumi. To keep your v4 output byte-for-byte, say so:

```ts
// v4
new ImageResponse(html, { width: 1200, height: 630 });

// v5, same output as before
new ImageResponse(html, { engine: "satori", width: 1200, height: 630 });
```

If you stay on the default, expect the Takumi differences: a built-in font (no fallback fetch), more formats (`webp`, `jpeg`, `ico`, `raw`), `emoji: "from-font"`, and a different layout engine, so pixels won't be identical to Satori's.

## 3. `./takumi` is the root entry

```ts
// v4
import {
  ImageResponse,
  type TakumiImageResponseOptions,
} from "@ethercorps/sveltekit-og/takumi";

// v5
import {
  ImageResponse,
  type ImageResponseOptions,
} from "@ethercorps/sveltekit-og";
```

The `/takumi` import keeps working as an alias (including the `Takumi*` type names) and is removed in v6.

## 4. One API, on the server and on `/client`

```ts
class ImageResponse<T> extends Response             // (element, options?, props?)
function createImage(element, options?, props?)    // → ImageResponse
function renderImage(element, options?, props?)    // → Promise<Uint8Array | string>  (svg → string)
```

- `createImage` returns a `Response`. If you were calling the old internal `createImage` for bytes, use `renderImage`.
- `renderImage` is new on `/client` too.
- `/client`'s `ClientImageResponseOptions` is now an alias of `ImageResponseOptions`.

## 5. Fonts: `resolveFonts` is optional

Both engines take `GoogleFont`, `CustomFont` or a raw `{ name, data, weight, style }` straight in `fonts`:

```ts
// v4
fonts: await resolveFonts([new GoogleFont("Inter", { weight: 700 })]);

// v5
fonts: [new GoogleFont("Inter", { weight: 700 })];
```

`resolveFonts` stays exported for pre-resolving and caching. `GoogleFont` works on the server with either engine; `/client` still exports only `CustomFont` (browsers can't fetch Google's TTFs).

## 6. `engine` narrows the options

Options are checked per engine. Omit `engine` (or `engine: "takumi"`) for `format` (any), `quality`, `stylesheets`, `emoji` incl. `"from-font"`, and a `takumi` pass-through to takumi-js. Use `engine: "satori"` for `format: "png" | "svg"`, `tailwindConfig`, and `satori` / `resvg` pass-throughs. Pass-throughs are spread last, so they win:

```ts
createImage(html, { format: "webp" }); // ok
createImage(html, { engine: "satori", format: "webp" }); // type error, and UNSUPPORTED_FORMAT at runtime
createImage(html, { engine: "satori", resvg: { background: "#fff" } });
createImage(html, { takumi: { signal: AbortSignal.timeout(5000) } });
```

## 7. Errors

- New codes: `ENGINE_NOT_INSTALLED` and `UNSUPPORTED_FORMAT`. On v4, `engine: "satori"` with `format: "webp"` silently rendered a PNG; v5 rejects.
- Codes now reach you intact. v4 wrapped every failure as `UNKNOWN_ERROR: Failed to generate PNG` with the real error in `originalError`; v5 throws the specific error itself (`FONT_LOAD_FAILED`, `UNSUPPORTED_FORMAT`, …), whether you read the body with `arrayBuffer()`, `fetch` the route, or prerender it.
- `ImageResponseError` and `ErrorCodes` are exported from the root and `/client`.

## 8. Component props are typed

A component with required props must get them; one with all-optional props may omit them; an HTML string can't be given props. Remove `as never` casts you added on v4 to get past the old signature.

## 9. Toolchain

- Peers: `svelte ^5`, `@sveltejs/kit ^2 || ^3`. SvelteKit 3 is supported; SvelteKit 2 still is.
- The `sveltekitOG()` plugin now returns an array of plugins. `plugins: [sveltekit(), sveltekitOG()]` keeps working (Vite flattens it).

## Checklist

- [ ] add `engine: "satori"` where v4 output must stay identical
- [ ] optional: `/takumi` import → root import; `Takumi*` types → `ImageResponseOptions` / `TakumiOptions`
